# Phonon / 포논

원본 근거와 연결된 한국어 입력·처리·출력 설명을 만드는 로컬 실험 도구입니다. 확인된 하위 의미를 먼저 확보하고, 현재 노드의 직접 처리와 하위 내부 설명을 구분합니다.

**상태: 원래 선정한 실제30노드·28그룹의 원본 품질·native 통합·무료 재사용과 CLI·UI·MCP 조회 검증을 완료했습니다.** 전체 프로젝트·모든 언어 패턴의 일반 정확성을 뜻하지 않으며 생성 결과는 계속 검수 대상으로 표시합니다.

## 실행

검증 환경은 Windows, Node.js 22.22.0입니다. 소스 등록 범위는 `D:\project`이며, 원본을 제자리에 두고 분석 데이터는 Phonon의 `.local`에 저장합니다. 원본 코드를 실행하거나 수정하지 않습니다.

```powershell
npm ci --cache .npm-cache --ignore-scripts
npm test
node cli.mjs register "내 프로젝트" "D:\project\my-project"
node cli.mjs projects
node cli.mjs status <project-id>
node cli.mjs analyze <project-id> 0 sample.py
node cli.mjs analyze <project-id> 0 sample.py --input-tokens=6000 --output-tokens=2000
node cli.mjs analyze <project-id> 0 --node=<node-id> --input-tokens=6000 --output-tokens=2000
npm run ui
```

검수 화면: `http://127.0.0.1:4317`. 분석 요청의 숫자는 신규 모델 호출 상한입니다. 기본 0은 유료 호출을 허용하지 않습니다. 유효한 캐시를 재사용하며 예산 부족·파싱·모델·품질 형식 실패는 이전 정상 결과를 보존합니다. CLI·UI·MCP는 같은 엔진을 사용합니다.

## 모델·비용·실패 처리

- OpenAI Agents SDK 0.20.0 / OpenAI SDK 7.32.0 / `gpt-6-luna`만 사용합니다. 루트 `.env`의 `OPENAI_API_KEY` 하나만 읽으며 환경 변수나 다른 키로 대체하지 않습니다.
- 기본 한도는 호출 0·입력 3000·출력 1000입니다. 요청당 설정 가능한 최대 호출 24·입력 19000·출력 8000입니다. 실제 세 함수의 순환 그룹이 출력2000·4000에서 잘려 관측된 범위의 지원 상한만 늘렸습니다. 실제 순환 그룹의 전체 입력 17597토큰이 기존 16000을 넘어 관측된 범위에 필요한 입력 상한만 늘렸습니다. 원본 기반 역할 목록을 포함한 실제 입력18228이18000을 넘은 관측에 대응해19000까지 지원합니다. 기존16000·18000 배정과 소비는 과거 기록으로 유지하며 새19000 배정은 별도 유한 계획을 따릅니다. 출력8000 지원과 실제 회차 배정은 구분합니다. 해당 순환 그룹만8000을 배정하고 기존 하위의2000 생성profile를 유지하는 배정은 공유 엔진의 선택적 outputAllocations로 수행합니다. CLI·UI·MCP의 기존 단일 출력한도 흐름은 유지하며 이 개별 배정은 현재 직접 엔진/실험 경로에서만 사용합니다. 이전 SQL4000 및 Python2000·4000 회차 기록은 보존합니다. 초기 소규모 검증은 입력 6000/출력 2000, 실제 Python 확대 회차는 입력 8000/출력 2000을 배정했습니다. 설정 최댓값은 실제 호출 배정과 구분합니다. 출력 한도가 달라지면 캐시 키도 달라집니다.
- 자동 재시도·외부 추적은 꺼집니다. 한 실행은 최대 1턴·1전송입니다. 전송 전에 원본·프롬프트·구조화 출력 스키마의 토큰을 추정하고 사용량을 별도로 기록합니다.
- SDK의 엄격한 구조화 출력과 ID·하위 의존·소유 참조·근거 범위·한국어 검증을 적용합니다. 형식·언어 검사는 설명 정확성을 보장하지 않습니다.
- 인증·키·모델·결제 등 Luna 자체 사용 불가만 `.local/api-stop.json`으로 지속 차단합니다. 출력 제한·잘못된 응답·요청 설정·일시 서버/전송 실패는 해당 작업을 종료합니다. 원인 수정 후 같은 모델·키와 새 한도에서 재검증할 수 있습니다.
- `ModelBehaviorError`는 미완료 응답을 읽지 못한 경우에도 발생합니다. 최초 실패의 정확한 원인은 미확정입니다. 별도 재현에서 HTTP 200/incomplete/max_output_tokens를 확인했고 원래 조건 재요청은 완료됐습니다. 후속 SQL의 45초 전송 시간 초과도 단일 재요청으로 완료됐습니다.

지속 차단의 원인을 해소하고 사용자 재개 승인을 받았을 때만 아래 명령을 사용합니다.

```powershell
node cli.mjs resume-api --confirmed-by-user
```

코드·하위 설명은 의미화 요청에서 외부 API로 전송됩니다. 환경파일·비밀·실제 고객 데이터의 전송은 허용하지 않습니다. 선택 범위의 비밀 패턴 검사도 수행합니다. 완전 오프라인 도구가 아닙니다.

초기 소형 개발 실험에서 의미화 요청 95회와 초기 연결 1회를 실행했습니다. 사용량을 확보한 93회는 입력 223,799·출력 35,318토큰, 캐시 읽기 140,881·쓰기 77,857토큰입니다. [공식 표준 단가](https://developers.openai.com/api/docs/models/gpt-6-luna)를 적용한 확보분 추정은 **USD 0.029306035**입니다. 초기 연결·과거 SDK 실패·전송 시간 초과 각 1회의 토큰/비용은 미확인입니다. 청구서 실제 결제 금액이나 Codex 개발 사용량을 합산한 값이 아닙니다.

## 구현·검증 범위

| 영역 | 구현과 실제 확인 | 경계 |
|---|---|---|
| Stage 1 | Tree-sitter: Python·TS·JS·TSX·JSX·HTML. CSS: PostCSS 8.5.29. SQL 파서: PostgreSQL 기본 문법과 명시적 선두 foreign_keys PRAGMA가 있는 SQLite. 함수·메서드·실행부·클래스 필드 초기화 소유자를 구분 | HTML 루트 구조, CSS 규칙, SQL 파일 단위 |
| Stage 2 | AST 바인딩/가림/직접 별칭, 분석 범위 내 명시적 import/export/reexport/namespace 연결, 실제 필드 읽기 참조 | 동적·모호한 대상은 확정하지 않음 |
| Stage 3 | H3 소유 범위 방식에 H2 사용 기반 입력 설명을 조합. 하위 우선, 실제 SCC는 멤버 원본을 한 응답으로 읽고 노드별 설명 | 상위 기능/프로젝트 목적 계층화는 보류 |
| 갱신 | 정확한 의미화 입력·생성 profile 캐시, 줄 이동 0회 재사용, 하위 변경의 상위 영향, 노드별 조건·과거 근거 보존 | 이동/이름 변경 동일성 미검증 |
| 인터페이스 | CLI·브라우저 UI·실제 stdio MCP에서 같은 결과 조회 및 0회 재사용 | 외부 사용자 AI 호스트 연결 미검증 |

검수된 SCC 컴포넌트는 직접 엔진의 `importReviewedMixedGroup`으로 생성 호출0에서 등록할 수 있습니다. 현재 원본·요청·하위 해시와 엄격한 계약 검증을 통과한 각 컴포넌트의 회차·생성 profile 출처를 별도로 보존하며, 정확한 혼합 전략 캐시를 재사용합니다. 기본 추론 none과 기존 CLI·UI·MCP 흐름은 유지하며 혼합 등록·그룹별 배정은 현재 직접 엔진의 고급 경로입니다. 실제 등록·재사용은 무료로 확인했고, 최종 선택 범위의 품질·출처 감사와 인터페이스 검증은 실험 이력을 따릅니다. 혼합 결과를 같은 회차의 새 공동 생성으로 표시하거나 기존 실패를 지우지 않습니다.

초기 무료 회귀 검사 **130개 통과**. 확대 과정의 검사·실제 소스 판정은 실험 이력에 별도로 기록합니다. 실제 작은 Luna 검증에서는 원본 Python 두 노드, 자체 작성 파일 간 호출·변경·순환·상태 참조·각 언어 문법 사례를 원본과 대조했습니다. Python 실제 프로젝트는 그래프 10개 중 선택한 2개 설명만 검수했으며 전체 프로젝트 검증이 아닙니다. 이 초기 소형 회차의 나머지 언어 사례는 자체 작성입니다. 이후 실제 원본 검증 범위는 실험 이력을 따릅니다.

마지막 초기 소형 통합 회차는 **새 호출 0회**로 통과했습니다. 조건·반환·계산·타입/객체 계약·출력 효과·하위 소유 범위·실제 근거 행을 독립 대조했습니다. 관측된 하위 조건 반복·영문 출력·상태 입력/효과 누락·근거 행 혼합은 해당 사례에서 해결했습니다. IPO 구간 사이의 일부 표현 반복은 남아 있어 완전한 비중복성이나 일반 프로그램 정확성을 보장하지 않습니다.

초기 **64파일·100노드 제한은 제거했습니다.** 전체 구조 맥락을 계산하고 유료 의미화는 파일 또는 노드 ID로 선택합니다. 둘을 지정하면 합집합이며 필요한 하위 의존성을 포함합니다. 첫 부분 분석은 미선정 상위를 자동 생성하지 않으며, 이미 설명된 상위의 전제가 영향을 받으면 갱신 범위에 포함합니다. 다른 노드의 이전 조건·의미 원본을 보존하며 미처리 변경/삭제는 오래된 상태로 남습니다. 분석 당시 조건과 생성 profile을 구분하므로 조건 메타 변경만으로 같은 의미 입력을 유료 재생성하지 않습니다. 기존 캐시는 정확한 요청과 현재 검증기를 통과해야 재사용합니다.

복잡한 동적 호출·상속·언어 간 관계·대형 프로젝트·모든 언어 패턴·설치 패키징은 미검증입니다. 정적 연결 후보·외부 경계·모델 불확실성을 숨기지 않습니다.

## MCP

```powershell
node src/mcp.mjs
```

stdio의 `list_projects`, `register_project`, `analysis_status`, `request_analysis`, `get_node`를 제공합니다. 요청은 `queued`/`running`과 작업 ID를 즉시 반환하고 상태 도구로 완료/실패를 조회합니다. 예산 생략은 호출 0입니다. 실제 SDK Client↔stdio 서버↔공유 엔진으로 5개 도구·근거·하위 버전·profile·캐시 재사용을 검증했습니다.

## 실험 기록·재현

`experiments/h1.mjs`, `h2.mjs`, `h3.mjs`는 세 독립 가설의 요청 구성입니다. 비교 이유, 실패, 보완과 한계는 [실험 이력](docs/experiment-notes.md)에 남겼습니다. `test/engine-real.mjs`는 초기 소형 통합 검사, `test/engine-extended.mjs`는 파일 간·순환·상태·각 언어 및 원본 두 노드의 소형 유료 검사입니다. 기본 무료 검사에 포함하지 않습니다.

```powershell
node test/engine-extended.mjs "D:\project\검토한-작은-프로젝트" "검토한-두-노드.py"
```

유료 검사는 실제 모델 호출 권한과 검토된 작은 원본이 필요합니다. 실행 계획/실제 결과/원본 대비 판정/사용량/실패 기록은 `.local`에 보존합니다. 형식 검사 성공과 설명 품질 검수는 구분합니다.

공개 저장소에는 구현·프롬프트·자체 작성 회귀 사례·실행 문서·빈 설정 예시만 포함합니다. `.env`, 다른 프로젝트 원본/생성 설명, 캐시·사용량·응답 로그는 제외합니다.
## 실제 프로젝트 확대 검증 결과

사용자 확정에 따라 기초 가설은 3개, 서브에이전트는 메인 외 3명입니다. 실제 Python 캐시 탐색 7노드와 혼합 SCC의 native 등록·정확한 무료 재사용을 확인했습니다. 선정30노드·28그룹의 마지막 상위3노드는144·146·147회차에서 각각 독립 원본 검수 PASS이며, 최종 선택 범위는 신규 호출0·30재사용·0생성으로 모두 최신입니다. 전체 무료419검사와 선정30의 최종 원본 품질·출처·하위 해시 감사가 통과했습니다. CLI subprocess·임시 소유 HTTP UI·실제 SDK stdio MCP에서30개 모두 같은 의미·근거 원본·하위 버전·현재 상태를 확인했고 추가 API 호출은0입니다. 프로젝트 구조143노드 전체의 품질 통과나 외부 사용자 AI 호스트 연결 완료를 주장하지 않으며 혼합 응답의 회차·profile 출처와 과거 실패를 보존합니다. 기본 none과 직접 엔진의 고급 옵션 경계를 유지하고 현행 이력·비용은 [실험 이력](docs/experiment-notes.md)을 따릅니다.
