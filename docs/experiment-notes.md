# 초기 비교·통합 이력

## 목표와 선택 근거

구체적이고 근거를 추적할 수 있으며 상하위 내부 처리 설명이 중복되지 않는 입력·처리·출력 설명을 목표로 했다. 기존 분석 이론의 함수·메서드·실행 top_level을 출발점으로 했으며 단계별 고정 산출물을 정답으로 전제하지 않았다. 구 TheCode의 Stage3은 SCC/계층 DAG, Stage4가 의미화였다.

H1은 원본과 모든 하위 의미를 전달했다. 첫 결과에서 상위가 하위 덧셈식을 반복했다. 반복을 억제한 뒤에도 로컬 리터럴을 상위 외부 입력처럼 분류했다.

H2는 구문 사실과 하위 입력/출력 계약을 전달하고 하위 process를 제외했다. 입력을 실제 연산 용도로 설명한 점은 유용했다. 구체 인자 해석을 강화한 뒤 상위 output에 하위 계산식을 반복했다.

H3는 직접 사실과 하위 소유 설명을 분리하고 같은 응답에서 ownerChecks를 작성했다. 반복과 로컬 입력 오분류를 피하여 기반으로 선택하고 H2의 사용 기반 입력 지시를 결합했다. ownerChecks는 모델 자기 기록이며 정확성 증거를 대신하지 않는다.

## 관측·수정·재검증

- Python 기본 print까지 미해결로 표시해 출력 효과 설명이 누락됐다. 이름 가림을 확인한 표준 builtin 계약을 넣고 같은 사례에서 출력 설명을 재확인했다.
- 파서 런타임과 문법 WASM의 호환 오류를 관측하고 문법 패키지에 맞는 런타임 0.20.8을 고정했다.
- 중첩 함수 미연결/전역 동명 함수 오연결, HTML 두 번째 루트 누락, CSS 규칙 ID 충돌, exported 변수 초기화 누락을 실제 회귀 사례로 확인하고 수정했다. 관련 검사 23개가 통과했다.
- 프로젝트 등록/상태 격리/실패 후 정상 결과 보존/동시 잠금/경로 이탈 거부 검사 5개가 통과했다.
- 실제 통합에서 조건·곱셈·하위 ID 이용과 상위의 하위 조건 비반복을 확인했다. 줄 이동은 신규 호출 0, 하위 동작 변경은 하위와 상위 2개 갱신, 문법 실패는 정상 스냅샷 보존을 확인했다.
- UI 기본 토큰 값이 엔진과 달라 0회 요청에서도 캐시가 빗나가는 문제가 나와 3000/1000으로 일치시켰다. 이후 프롬프트 변경으로 최종 상위 캐시 재검증은 아직 완료하지 못했다.
- H3 하위 참조가 모호한 결과를 관측했다. 책임명을 강화하자 판별 기준을 '음수'로 반복하고 else를 코드에 없는 <= 비교로 바꾼 결과가 나와 v6에서 보완했다. CSS의 출력 빈 배열도 관측하여 선언형 언어 규칙 결과를 기술하도록 보완했다.
- v6의 하위 생성 후 상위 SDK 실행에서 ModelBehaviorError가 발생했다. 유료 실험을 중단하고 정상 스냅샷을 보존했다. 오류 타입만으로 인증 문제·응답 미완료·출력 품질 문제 중 어느 원인인지 확정하지 않았다. 다음 실행의 HTTP상태/응답상태/미완료 이유/토큰만 안전하게 기록하는 진단을 추가했다. 이 당시에는 실제 API로 재시험하지 않았다. 이후 재개와 재현 결과는 아래에 기록한다.

## 비용과 판정의 한계

Luna 표준 토큰 단가로 사용량 비용을 추정하고 캐시 입력을 분리했다. 연결 점검 첫 1회는 로컬 기록 오류로 토큰이 미확인이고 마지막 SDK 실패 1회도 usage를 확보하지 못했다. 청구서 실제 결제 금액으로 표현하지 않는다. 실제 로그와 원본 대비 결과는 공개하지 않고 로컬 `.local`에 보존한다.

당시 최종 재검증은 중단 상태였다. 이후 사용자가 Luna 사용 불가 외 오류의 자율 수정·재검증을 승인했다. 소규모 통과를 전체 언어·큰 프로젝트 지원으로 확대하지 않는다.
## 같은 Luna로 오류 진단과 재개

같은 실패 상위 요청을 기존 출력 상한 1000으로 재요청하여 HTTP 200 / completed, 입력 2896·출력 797토큰을 확보했다. 따라서 Luna 연결 자체의 실패는 아니었다. 별도 기존 소형 요청을 출력 상한 64로 제한한 재현에서는 HTTP 200 / incomplete / max_output_tokens와 SDK ModelBehaviorError가 함께 발생했다. **최초 실패 당시 종료 이유가 없으므로 최초 실패도 같은 원인이라고 단정하지 않는다.**

모든 SDK 오류를 모델 사용 불가로 취급한 지속 차단 정책을 수정했다. HTTP 상태·응답 종료 상태·안전한 오류 코드로 인증/키/모델/결제 차단과 출력/요청/일시 서비스 실패를 구분한다. 재시도를 자동 반복하지 않으며 실패한 작업은 종료하고 기존 정상 결과를 보존한다. 사용자는 동일 모델·지정 키로 원인 확인과 작은 재검증을 자율 수행하도록 승인했다.

H3 v7에서는 소유 확인 문장 반복을 section/index/ownerId 참조로 줄이고 본문 줄번호를 제거했다. 실제 조건부 상하위 2개, CSS 1개, 새 TypeScript 상하위 2개를 생성해 원본과 대조했다. 상위의 하위 조건 동의어 반복과 코드에 없는 else 보수식이 없어졌고 CSS 출력 규칙을 확인했다. 각 사례의 0회 캐시 재사용도 통과했다.

기존 비용 계산에서 캐시 쓰기 추가 단가를 누락했으므로 이후 집계는 입력/캐시 읽기/캐시 쓰기/출력을 나누어 재계산한다. 기존 실패 기록과 당시 추정은 보존하며 실제 청구 금액으로 표시하지 않는다.

## 원래 범위 재점검과 통합 중인 수정

무료 실제 소형 소스 조사에서 지역 변수에 가려진 함수를 전역 함수로 연결한 오류, Python 반복 변수 print를 builtin으로 분류한 오류, 직접 함수 별칭 미연결, 클래스 필드 초기화 누락, 새 파일 추가 누락, 부분 갱신 후 이전 조건 설명을 최신으로 표시한 오류를 관측했다. AST 바인딩·import/export 메타데이터·클래스 초기화 소유자·노드별 분석 조건을 보완했다.

파일 간 명시적 import/reexport 연결과 순환 의존 그룹 처리는 원래 요구이므로 추가 통합한다. 순환 그룹의 내부 설명을 이미 완성한 것처럼 만들지 않고 모든 멤버 원본을 한 응답으로 읽어 멤버별 소유 설명을 반환한다. 실제 필드 참조는 호출과 구분하며 초기화를 다시 실행한다고 설명하지 않는다. 무료 구조/검증기 통과와 실제 Luna 의미화 검증을 구분해 기록한다.
## 최종 통합·정밀 검수

파일 간 명시적 Python/JS/TS 연결을 엔진에 통합하고 실제 상태 참조와 확인된 SCC를 하위 우선 순서에 포함했다. 부분 갱신은 선택 노드의 역영향 및 필요한 전방 의존을 재계산한다. 미처리 노드는 이전 조건·소스 지문·설명 원본을 보존하고, 삭제되거나 바뀐 노드를 최신으로 숨기지 않는다. 근거는 생성 당시 원본으로 매핑한다.

실제 순환 결과는 형태 검사에 통과해도 상대 조건/반환을 복제하거나 영어로 출력되는 문제가 있었다. 최소 하위 역할 및 알려지지 않은 제약만 설명하도록 지시를 보완하고 한국어 검사기를 연결했다. 후속 응답이 ownerChecks에 uncertainty 항목을 추가해 거부돼 SDK의 strict structured output을 적용했다. 소유 표시가 맞다는 것만으로 설명의 사실성을 보장하지 않는다.

클래스는 기존 상태 입력과 초기화·갱신 효과 출력이 누락돼 H3에 실제 상태 읽기 및 초기화 소유 문맥을 보완했다. static 정의 평가와 instance 구성 시점을 구분하며, 필드 참조를 초기화 재실행으로 설명하지 않는다. TSX/JSX 객체 구조분해, 명시된 string 계약, 무시된 print None 반환의 상위 출력 혼입도 원본 대조 후 보완했다.

한 근거 문장이 조건 행과 다음 반환 행을 묶은 문제를 관측해 행별 근거 분리를 보완했다. 최종 결과는 조건/반환 근거가 각각 실제 행에 맞았다. CSS output의 그리드는 grid의 정확한 번역인데 검사기가 영어만 받아 실패한 오판도 고쳤다. 마지막 SQL 전송 시간 초과는 동일 작은 요청 1회 재확인으로 완료됐으며 실패 이력은 남겼다.

조건 source hash를 의미 캐시 키에 그대로 넣어 실행 정보만 바뀌어도 유료 재생성이 필요한 문제가 드러났다. 분석 조건은 최신성 검수에 보존하되 의미 재사용은 정확한 요청과 실제 생성 profile로 결정한다. 기존 캐시 키도 같은 요청으로 재구성하고 현재 strict schema/ID/child/evidence/owner/Korean 검증을 통과할 때만 새 캐시 키로 복사한다. 기존 로그·캐시 원본은 유지했다. API 0회 synthetic native 검증은 캐시/상태 경로 증거이며 실제 설명 품질 증거로 표시하지 않는다.

최종 무료 검사 130개와 실제 소형 통합 검증을 통과했다. 마지막 동일 통합 회차는 추가 모델 호출 0회다. 독립 원본 대조에서 앞선 관측 실패의 재발은 없었다. 다만 JS 등에서 같은 계산 의미가 IPO 구간 사이에 일부 반복된다. 따라서 완전 비중복성·전체 언어/대형 프로젝트 지원이나 일반 프로그램 정확성을 완료로 표현하지 않는다. 실제 프로젝트는 그래프 10개 중 선택 2개만 설명 검수했으며 다른 언어 사례는 자체 작성 작은 소스다.

최신 CLI·브라우저 UI·실제 stdio MCP는 캐시 2개/새 생성 0개로 공유 엔진 흐름을 확인했고 UI 콘솔 오류 0개였다. 외부 사용자 AI 호스트 연결은 미검증이다. 새 모델·새 키·원본 수정 도구·상위 목적 계층화는 추가하지 않았다.

## 최종 사용량과 공개 경계

의미화 요청95회+첫 연결1회. 사용량 확보93회 입력223,799/출력35,318, 캐시읽기140,881/쓰기77,857토큰. 공식 표준 단가로 확보분 추정USD0.029306035이며 첫 연결/과거SDK실패/SQL전송시간초과의3회 사용량은 미확인이다. 사람 품질검수에 실패한 응답도 형태가 유효하면 response_valid 로그로 남을 수 있으므로 이 수치를 정확성 통과율로 쓰지 않는다. Codex 개발 사용량과 SDK 비용을 합산하지 않는다.

세션의 공개 푸시는 사용자가 지속 승인했다. API 키, 실제 원본/의미 설명, 캐시/응답/사용량은 제외한다. 구현·프롬프트·자체 회귀 사례·문서·빈 설정만 저장하며 최종 commit은 Git 이력에서 확인한다.
