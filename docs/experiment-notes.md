# 초기 비교·통합 이력

## 목표와 선택 근거

구체적이고 근거를 추적할 수 있으며 상하위 내부 처리 설명이 중복되지 않는 입력·처리·출력 설명을 목표로 했다. 기존 분석 이론의 함수·메서드·실행 top_level을 출발점으로 했으며 단계별 고정 산출물을 정답으로 전제하지 않았다. 구 TheCode의 Stage3은 SCC/계층 DAG, Stage4가 의미화였다.

H1은 원본과 모든 하위 의미를 전달했다. 첫 결과에서 상위가 하위 덧셈식을 반복했다. 반복을 억제한 뒤에도 로컬 리터럴을 상위 외부 입력처럼 분류했다.

H2는 구문 사실과 하위 입력/출력 계약을 전달하고 하위 process를 제외했다. 입력을 실제 연산 용도로 설명한 점은 유용했다. 구체 인자 해석을 강화한 뒤 상위 output에 하위 계산식을 반복했다.

H3는 직접 사실과 하위 소유 설명을 분리하고 같은 응답에서 ownerChecks를 작성했다. 반복과 로컬 입력 오분류를 피하여 기반으로 선택하고 H2의 사용 기반 입력 지시를 결합했다. ownerChecks는 모델 자기 기록이며 정확성 증거를 대신하지 않는다.

## 관측·수정·재검증

- Python 기본 print까지 미해결로 표시해 출력 효과 설명이 누락됐다. 이름 가림을 확인한 표준 builtin 계약을 넣고 같은 사례에서 출력 설명을 재확인했다.
- 파서 런타임과 문법 WASM의 호환 오류를 관측하고 문법 패키지에 맞는 런타임 0.20.8을 고정했다.
- 중첩 함수 미연결/전역 동명 함수 오연결, HTML 두 번째 루트 누락, CSS 규칙 ID 충돌, exported 변수 초기화 누락을 실제 회귀 사례로 확인하고 수정했다. 관련 검사 23개가 통과했다.
- 프로젝트 등록/상태 격리/실패 후 정상 결과 보존/동시 잠금/경로 이탈 거부 검사 5개가 통과했다.
- 실제 통합에서 조건·곱셈·하위 ID 이용과 상위의 하위 조건 비반복을 확인했다. 줄 이동은 신규 호출 0, 하위 동작 변경은 하위와 상위 2개 갱신, 문법 실패는 정상 스냅샷 보존을 확인했다.
- UI 기본 토큰 값이 엔진과 달라 0회 요청에서도 캐시가 빗나가는 문제가 나와 3000/1000으로 일치시켰다. 이후 프롬프트 변경으로 최종 상위 캐시 재검증은 아직 완료하지 못했다.
- H3 하위 참조가 모호한 결과를 관측했다. 책임명을 강화하자 판별 기준을 '음수'로 반복하고 else를 코드에 없는 <= 비교로 바꾼 결과가 나와 v6에서 보완했다. CSS의 출력 빈 배열도 관측하여 선언형 언어 규칙 결과를 기술하도록 보완했다.
- v6의 하위 생성 후 상위 SDK 실행에서 ModelBehaviorError가 발생했다. 유료 실험을 중단하고 정상 스냅샷을 보존했다. 오류 타입만으로 인증 문제·응답 미완료·출력 품질 문제 중 어느 원인인지 확정하지 않았다. 다음 실행의 HTTP상태/응답상태/미완료 이유/토큰만 안전하게 기록하는 진단을 추가했다. 이를 실제 API로 재시험하지 않았다.

## 비용과 판정의 한계

Luna 표준 토큰 단가로 사용량 비용을 추정하고 캐시 입력을 분리했다. 연결 점검 첫 1회는 로컬 기록 오류로 토큰이 미확인이고 마지막 SDK 실패 1회도 usage를 확보하지 못했다. 청구서 실제 결제 금액으로 표현하지 않는다. 실제 로그와 원본 대비 결과는 공개하지 않고 로컬 `.local`에 보존한다.

현재는 초기 구현·소규모 통과·최종 재검증 차단 상태다. 파일 간/언어 간 관계·순환·큰 프로젝트를 지원 완료로 표시하지 않는다. 다음 작업은 사용자 재개 확인 후 동일 Luna·지정 키로 최소 범위에서 오류를 구분하고 마지막 상위/CSS 품질을 재검증하는 것이다.
